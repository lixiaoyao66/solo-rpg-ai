# Tasks

## 1. 数据库和后端基础

- [ ] 1.1 在 Supabase 中创建 `characters` 表，包含所有字段（基础信息、属性、战斗数据、技能 JSON、装备 JSON、背景故事、立绘 URL 等），验证表结构正确且外键关联 `users` 表
- [ ] 1.2 创建后端 DND 5e 规则数据文件（`src/data/dnd/rules.py`），包含种族、职业、背景、技能列表、属性调整值计算函数，验证数据完整性和计算正确性
- [ ] 1.3 实现角色 CRUD API 端点（`POST /api/characters`、`GET /api/characters`、`GET /api/characters/{id}`、`PUT /api/characters/{id}`、`DELETE /api/characters/{id}`），使用 Pydantic 模型验证请求数据，验证 API 可正常创建和读取角色

## 2. 角色创建核心逻辑

- [ ] 2.1 实现属性分配逻辑：标准数组分配、购点法（27 点）、掷骰法（4d6 去最低），包含属性调整值自动计算，验证三种方式都能正确计算调整值
- [ ] 2.2 实现种族和职业选择逻辑：选择后自动应用属性加值、初始 HP、熟练技能、初始装备，验证选择人类 + 战士后属性、HP、技能正确
- [ ] 2.3 实现技能熟练选择和加值计算：根据职业和背景提供可选技能列表，限制选择数量，自动计算技能加值（属性调整值 + 熟练加值），验证技能加值计算正确
- [ ] 2.4 实现战斗数据自动计算：HP（生命骰最大值 + 体质调整值）、AC（根据装备类型）、先攻（敏捷调整值）、速度（种族基础速度），验证计算结果符合 DND 5e 规则
- [ ] 2.5 实现角色创建规则验证：检查属性值范围（3-20）、技能选择数量、装备限制等，验证违规数据被正确拒绝并返回错误信息

## 3. 随机角色生成

- [ ] 3.1 实现后端随机角色生成服务（`src/services/character_generator.py`），支持完全随机和部分偏好随机（指定种族/职业），验证生成的角色符合规则
- [ ] 3.2 实现随机生成 API 端点（`POST /api/characters/generate`），接受偏好参数，返回完整角色数据，验证 API 响应格式正确
- [ ] 3.3 集成 Claude API 生成背景故事：根据种族、职业、背景生成 200-500 字的背景故事草稿，验证故事内容合理且与角色设定一致

## 4. 前端角色创建页面

- [ ] 4.1 创建角色创建页面框架（`/characters/new`），包含三种创建方式选择（自建、随机生成、预设模板）的 Tab 切换 UI，验证页面可正常访问和切换
- [ ] 4.2 实现自建模式表单：种族选择器、职业选择器、背景选择器，选择后显示对应特性说明，验证选择后 UI 正确更新
- [ ] 4.3 实现属性分配器组件：三种分配方式（标准数组、购点法、掷骰法）的 Tab 切换和独立 UI，实时显示属性调整值，验证三种方式都能正确分配和计算
- [ ] 4.4 实现技能选择器组件：显示职业可选技能列表，限制选择数量，实时显示技能加值，验证选择数量和加值计算正确
- [ ] 4.5 实现装备选择器组件：显示职业初始装备选项，选择后自动更新 AC 和背包，验证 AC 计算正确
- [ ] 4.6 实现背景故事输入框和 AI 生成按钮：调用后端 API 生成背景故事，支持编辑，验证生成和编辑功能正常
- [ ] 4.7 实现角色立绘选择器：AI 生成（调用后端 API）、上传图片、预设头像库选择三种方式，验证三种方式都能正确保存立绘 URL

## 5. 角色卡预览和保存

- [ ] 5.1 实现角色卡预览组件：显示完整角色卡（属性、技能、装备、背景故事、立绘），布局与游戏内角色卡一致，验证预览内容完整且格式正确
- [ ] 5.2 实现保存前规则验证：调用后端验证 API，显示验证错误（如有），阻止保存，验证违规数据无法保存
- [ ] 5.3 实现保存功能：调用 `POST /api/characters` 保存角色，保存成功后跳转到角色详情页面或仪表板，验证保存后数据正确且页面跳转正确
